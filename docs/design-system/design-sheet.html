TacitSNS Design Sheet

Baseline visual contract for the CHI prototype. The target is a premium editorial tool for small business owners with low design literacy: calm, clean, minimal, and clearly not generic AI UI. The product flow is now hierarchy-first and staged: login, brand setup, business goals, post-goal setup, main workspace, then the 2x2 studio and traceboard.

Direction

Design direction: premium editorial light mode. Use warm paper backgrounds, ink-forward typography, a restrained deep-teal action color, rounded but not toy-like geometry, and clear visual hierarchy. Preserve trace-board semantics and spatial precision even when surrounding surfaces are restyled.

Product Hierarchy

Login

Simple prototype entry. Calm, confident, and non-threatening. It should feel like the front door, not the whole product.

Brand Setup

Brand identity and background come first so the system has enough context to infer broad business goals.

Business Goals

Keep these broad and outcome-based: trust, awareness, education, engagement, sales, and community. Plain language first.

Post-Goal Folders

Folders are narrower content directions under a business goal. Taxonomy tags support them, but do not lead the interaction.

Component Language

Buttons

Generate Ideas Regenerate Unavailable
There are only three button families in the system: primary CTA, secondary surface button, and choice/chip button. Primary and secondary buttons should stay in sentence case, while compact choice controls may use uppercase. Primary buttons must be clearly visible at rest. Hover may enhance depth, but never supply the only contrast. The main generation CTA should use a clearly higher-contrast hero treatment than other primary actions.

Fields

Enter your brand name
Inputs stay quiet and bright, with accent color appearing on focus rather than in the resting state. Brand identity and positioning should be collected through one guided narrative field rather than multiple fragmented textareas.

Feedback Chips

Liked Disliked Unsure Selected rationale
Feedback semantics may stay vivid, but surrounding cards and chrome should remain quiet.

Text Hierarchy

Display and heading text use serif for framing. Labels and metadata may use compact uppercase sans, but primary and secondary buttons should stay in sentence case.

Button Mapping
Primary CTA: continue to business goals, continue to post goals, continue to main workspace, create post-goal folder, generate ideas, generate variations, use this post, apply edit.
Secondary surface button: back, open workspace state, regenerate, history, debug navigation, drawer entry actions.
Choice / chip button: feedback toggles, rationale chips, direction chips, edit chips, compact overlay actions.
Guided Studio Flow
Flow: the studio should now move through `quick grid triage -> guided one-image critique -> generation brief -> regenerate`.
Grid: keep the 2x2 grid fast. Users only mark Like, Dislike, or Unsure. No rationale chips or note fields live there anymore.
Guided critique: the system should feel like an expert art director talking through one image at a time, with one main question, reason chips, an optional short note, and only one micro follow-up when needed.
Reason chips: some chips should be deliberately probe-worthy or goal-level so the system knows when to ask one micro follow-up now or one macro challenge at the end.
Hard to answer: every guided step should allow a `Hard to answer` path that opens a few concrete interpretation options, then lets the user either pick one or leave the signal unresolved.
Brief: the final surface should read as a synthesis card, not a dashboard. It must clearly show Keep, Avoid, Open tradeoff, and Next exploration.
Copy: keep the studio terse. Prefer one short guide line, one question, and one action block over stacked explanatory text.
Add-Card Pattern
Custom goals: custom business goals and custom post goals should appear as add-cards within the same planning surface as the recommended cards.
Dialog entry: clicking an add-card should open a focused writing dialog instead of expanding a long inline form.
Post-goal branching: custom post-goal creation should first branch between reference-image input and text-only input.
Post-goal browser: post-goal onboarding should feel like a visual browser, not a repeated business-goal card grid.
Inspectable post goals: suggested post goals should open into an inspectable detail pane with larger SNS-style example imagery and quiet taxonomy evidence before the user chooses them.
Discovery first: selected folders should be surfaced after or beneath exploration so browsing comes before management.
AI fallback: suggested post goals should try an AI-backed recommendation pass first, but a deterministic fallback library must prevent empty onboarding states.
Reference images: users should be able to attach their own example image to a post goal, and that reference should stay visible as the folder moves into the workspace and studio.

Research-Specific Rules

Trace board: preserve the exact internal layout logic, node sizing behavior, edge labels, and feedback-border semantics unless explicitly redesigned as a trace-specific task.
Preference capture: yes / no / unsure must remain visually explicit and easy to compare across the 2x2 grid.
Guided critique tone: once triage is complete, the system should feel like a confident expert guiding taste discovery one image at a time, not a passive review form.
Clarification timing: image-level clarification belongs inside the guided interview after a reason is chosen. Macro clarification belongs after cross-image synthesis, not as a side effect of grid rating.
Goal hierarchy: business goals must be visible before post-goal folders, and post-goal folders must clearly nest under an active business goal.
Staged onboarding: brand narrative, business goals, and post goals should be separate steps before the user lands in the main directory workspace.
Step markers: numbered progress markers need strong resting-state contrast and explicit active/completed states.
Motion safety: entering or exiting panels must not be clickable during slide transitions.
Workspace language: show plain-language goals first and keep taxonomy labels as quiet supporting metadata.
Clarification moments: when the system asks follow-up questions later, those interactions should feel editorial and confident, not chatbot-like.
Buttons: primary actions must remain legible and discoverable without hover. Secondary actions should stay visible through border and text contrast alone.
Grids: grid cards should support comparison first, spectacle second. Keep media square, chrome light, and selection states precise.
Scroll areas: long panels, debug surfaces, and history views should use integrated custom scrollbars that match the paper-toned surface system.
Anti-patterns: no purple AI gradients, no generic SaaS dashboard glass cards, no “vibe-coded” neon polish, no decorative metrics.
